## 4. Locale / fallback

- Copy is **English-only** (hardcoded in sender; no `emailLocales` builder).
- `HTMLLang` = `"en"`, `HTMLDir` = `"ltr"` always.
- No profile-language selection and no locale fallback path.

## 5. Invitation URL / token

- Invite link: `fmt.Sprintf("%s/organizer-team/invites/%s", config.AppConfig.URL, invitation.Token)`
- Existing user: primary CTA `ButtonURL` = invite link; secondary link = invite link
- New user: primary CTA `ButtonURL` = `signupURL` (`https://www.eveenty.com/register`); secondary link = invite link
- Token is opaque string from `model.OrganizerTeamInvitation.Token` (generated by caller/DB, not by the email package)

## 6. Conditional branches (`userExists`)

| Branch | Subject / heading / CTA |
|---|---|
| `userExists == true` | Accept-invitation copy; CTA = invite link; ToName = `Eveenty Organizer` |
| `userExists == false` | Create-account copy; CTA = signup URL; secondary = invite link; ToName = `Eveenty User` |

No other template-level `{{ if }}` conditionals beyond Kit RTL shell checks (`HTMLDir` is always `ltr` today).

## 7. Dynamic links

- Primary CTA: `ButtonURL` (invite or signup as above)
- Secondary text link: `SecondaryLinkURL` (always invite link)
- Footer mailto: Kit branded footer uses `UserEmail`
- Brand logo: `BrandLogo` via `applyKitBrandLogo("en", "https://cdn.eveenty.com/eveenty-logo-1280.png")` when Kit active

## 8. HTML-safe / raw surfaces

- Field names `BodyFirstHTML` / `BodySecondHTML` currently receive **plain text** from the sender (no markup).
- Kit template applies `| html` to heading/body/button/secondary label.
- CTA hrefs and secondary href are raw URL surfaces (same as other Kit templates).

## 9. MIME / attachments

- Kit active: `deliverRendered` wraps HTML as `multipart/alternative` (derived text/plain) — documented Kit MIME difference
- Attachments: **none**
- No ICS / pkpass / CID references
